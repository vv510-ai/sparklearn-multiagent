# 个人普通 Chat「一图看懂」接入

本次按用户要求保留普通 Chat 网页生图，不切换图片 API，不增加管理面板。接入默认关闭，只为一个已经核实的 LearnLoop 账号启用；其他客户继续使用现有图片服务。

## 使用流程

本机运行接入程序并保持 Chrome 登录 ChatGPT。用户在 LearnLoop 点原有「一图看懂」：网站准备并核对知识底稿 → 持久任务排队 → 本机新建普通 Chat 对话 → 发送一次提示 → 等图片完成 → 打开图片预览 → 通过现有授权连接读取预览中已加载的原图 → 自动回传 → 网站保存图片、核对结果和文字版。正常流程不需要复制提示词或手动上传。

程序运行期间复用专用 CLI 连接，退出、单次验证结束或出现异常时断开；不关闭用户 Chrome，不安装开机启动。Windows 后台接入由本人手动启动的普通权限任务运行，没有登录或定时触发器，不依赖 Codex 对话持续运行。首次连接可能需要在 Chrome 中允许调试。电脑关机、睡眠、断网或程序未运行时不能代替本机生成。

## 改动范围

- `services/personal_image.py`、`api/personal_image.py`、`PersonalImageJob`：账号绑定、一次一项领取、租约、提交前确认、超时和有界原图接收。
- 统一多模态网关与 `one_page_image.py`：仅绑定账号使用 `chatgpt_web`，禁止失败后转用图片 API；沿用现有文字、公式、关系检查，检查失败最多按现有规则修正一次。
- BFF 与认证中间件：独立配对令牌仅能访问图片接入接口，不能作为网站登录凭据；远程传输要求 HTTPS。
- `StudyArtifactBlocks.tsx`、评估摘要及生成状态：显示原图、未完成/待核对提示与文字版。图片返回成功不等于内容正确。
- `personal_chat_image_worker.py`、配对和启动脚本：官方 Chrome DevTools CLI 操作可见页面；原图限定为本次对话唯一预览中已经加载的 Blob，通过同一连接保存，并核对 MIME、字节数、尺寸及 SHA-256。不另开浏览器调试连接，不读取 Cookie、账号令牌或调用 ChatGPT 私有接口。
- `manage_personal_chat_image.ps1` 与 `run_personal_chat_image_background.py`：显式启动、查询或停止当前用户的后台任务，保存私有日志，正常退出时断开浏览器。空闲时连接网站的暂时网络错误持续等待恢复，退避间隔最多 60 秒，停止指令仍可立即响应。生成期间仅原任务保活可在 90 秒预算内恢复，给 180 秒服务端租约留出请求耗时余量；鉴权失败、租约拒绝、额度限制及其他不确定错误仍停止，不自动重发图片。

## 配置

服务器私有环境文件设置：

```dotenv
PERSONAL_CHAT_IMAGE_ENABLED=true
PERSONAL_CHAT_IMAGE_OWNER_ID=<已核实的 LearnLoop user_id>
PERSONAL_CHAT_IMAGE_WORKER_TOKEN_SHA256=<本机配对工具生成的 SHA-256>
```

同时需要原有真实模式、图片功能及持久任务配置启用：`DEMO_MODE=false`、`MM_IMAGE_ENABLED=true`、`GENERATION_JOBS_ENABLED=true`。后端与 generation-worker 使用一致的上述环境。

在本机已安装 Python 依赖及官方 Chrome DevTools CLI 后，用 `scripts/pair_personal_chat_image.py --help` 查看参数。指定网站 HTTPS origin、已核实账号 ID、Node/CLI 路径、Chrome 实际下载目录和用户私有状态目录。工具生成随机配对令牌，仅将明文保存在本机 `worker.json`，输出给服务器的只有哈希。拒绝覆盖已有配对，避免静默换令牌。配对文件与状态目录不得提交到 Git。

后台启动：`scripts/manage_personal_chat_image.ps1 -Config <本机 worker.json 路径> -Action Start`，用 `Status` 查询、`Stop` 请求正常退出。首次运行注册没有触发器的当前用户 Windows 任务，后续复用同一任务；不会提升权限或设置开机启动。部署时将管理脚本、后台入口与 worker 一起复制到本机私有运行目录。本机已提供 `D:\Desktop\知行循证LearnLoop\普通Chat生图接入` 中的启动、停止快捷方式。

前台检查仍可用 `scripts/start_personal_chat_image.ps1 -Config <本机 worker.json 路径>`。首次可附加 `-CheckBrowser` 只检查登录和连接；`-Once` 完成一项后断开退出；另开命令附加 `-Stop` 可要求当前程序结束等待、断开浏览器并退出。连续模式在无任务时低频轮询，不自动点击重试。停止程序后服务器仍保留已完成图片。

## 故障与安全边界

- 登录失效、验证码、浏览器授权、额度限制或页面改版时停止，交由本人处理。没有账号池、代理轮换或规避限额机制。
- 发送前持久确认；发送结果不明确时停止，防止自动重复消耗额度。过期任务不发送，旧心跳不能影响新任务。
- 已完成图片上传可幂等重试，但不同图片不能覆盖同一任务。仅接受有效 PNG/JPEG/WebP、20 MB 以内、非动画及受限像素数；原图归属绑定到本人，另一账号不能读取。
- 取图时要求当前对话地址一致、唯一图片预览可用且下载按钮未禁用；只读取浏览器已经展示的 `blob:https://chatgpt.com/` 内容，不请求图片后端接口，不用截图或公共下载目录中的同名文件代替原图。临时图片数据读完即清理。
- 配对令牌不是 ChatGPT 令牌，不授予聊天、课程、账号设置等业务 API 权限。撤销时关闭服务端开关并停止本机程序；泄露时重新生成配对并更新服务端哈希。
- 原生网页路线依赖页面结构和 Chrome 状态，不是 OpenAI 提供的受支持后台图片 API。普通 Chat 页面已实测生图；尚未对账证明具体额度扣减，不能承诺全天候稳定或其他用户可共用订阅。

### 2026-10-15 中断与响应耗时优化

用户反馈原文：“刚刚测试的时候 很容易中断出现问题 而且响应时间很慢”，要求“查清问题 并进行优化 测试 确保整个流程流畅”。

已复现的原因及修改：

- 本机 `urllib` 默认读取 Windows 代理设置，连接本站也经过本机代理。同一公开健康接口的 12 次对比中，原路径 11 次成功、中位耗时 2.914 秒，另 1 次在 8.094 秒超时；网站直接连接 12/12 成功，中位 0.172 秒、最大 0.203 秒。这证明当前网站连接路径有显著延迟和超时；旧日志未保存具体异常，不能将所有历史失败归为同一原因。
- 在本机私有 `worker.json` 设置 `"site_connection": "direct"` 后，仅配对网站的请求使用直接连接。缺省值仍为 `system`；不改变 Chrome、ChatGPT、Windows 代理或 TLS 校验，不自动切换代理。
- 等待外部图片时，原任务每 5 秒重新运行生成图并重建事件，造成进度重置。现在只检查图片交接状态，保留已展示事件及游标；完成、失败或过期后再继续原流程。前端继续使用原有持久任务状态，不新增消息类型。
- 发送前确认允许对同一租约进行有界重试，确认后仍只点击一次发送。原图回传遇到暂时网络失败时继续传同一字节；服务端已保存但响应丢失时可取回同一结果，拒绝不同图片覆盖。401/403/409/413/422/429 等不可恢复拒绝不自动重试。
- 记录连接、准备、发送、等待绘图、取图及上传耗时；网络日志只记录时间、请求类别、异常类别和数值错误码，不保存令牌、提示词或浏览器正文。原图路径与指纹在后续失败记录中保留，便于有依据地恢复。
- 图片状态检查从 4 秒间隔改为 2 秒，空闲领取从 5 秒改为 2 秒；仍须两次稳定图片状态，不跳过下载可用性、原图完整性和内容核对。
