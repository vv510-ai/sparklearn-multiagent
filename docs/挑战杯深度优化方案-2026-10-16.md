## 1. 前端设计与 UI：绿色「液态玻璃」系统
**目标**：保持绿色主调，做到“答辩投屏也好看”；不引入重依赖、不牺牲可读性。

1. **设计令牌重建**：深林绿 `#06281F` / 主绿 `#0E7A5A` / 青绿 `#12A38A` / 薄荷 `#7EE2B8` / 暖金点缀 `#F2C46D`；三档玻璃（面板 / 卡片 / 浮层）：半透明白 + `backdrop-filter: blur() saturate()` + 顶部 1px 镜面高光 + 柔和投影（借鉴 Apple Liquid Glass）；统一圆角、阴影、描边。
2. **背景**：本地 CSS 极光渐变网格（缓慢漂移 + 噪点）替换远程 CloudFront 视频；`prefers-reduced-motion` 时静止；离线可用、首屏更快。
3. **登录页**：品牌主张 + 三大核心能力（一图看懂 / 讲解视频 / 记忆歌曲）动态展示 + 玻璃登录卡。
4. **工作台**：玻璃导航；资料 / 对话 / 学习闭环工坊三栏；生成中 shimmer 与后端阶段一一对应的进度；统一提示样式。
5. **结果展示升级**：一图看懂 **多图画廊**（缩略图 + 大图 + 放大 + 下载全部 + 每张核对状态）；记忆歌曲 **双版本播放器 + 逐句高亮歌词 + 口诀卡 + 跟唱填空**；讲解视频 **MP4 播放器 + 讲稿/分镜**。
6. 移动端回归截图。

## 2. 「一图看懂」提示词重构（按你的要求极简化）

### 2.1 发给 ChatGPT 网页的提示词（完全采用你的模板）
```
帮我弄一个一图看懂{主题}的内容，如果一张图不够全面的解释或无法完整讲清楚，根据内容合理拆分为多张（合理数量）的一图看懂，确保内容全面、准确、直观易懂。
```
- `{主题}` 由“主题解析”从当前请求/对话中提取（如“光合作用的光反应与暗反应”），不会把“帮我生成一图看懂”这类操作语当主题。
- 只有学习者**选了自己的资料且设为“只依据资料”**时，才在末尾追加一行“请以我的资料要点为准：……”（≤1500 字），否则保持纯模板。

### 2.2 链路变化
| 旧链路 | 新链路（ChatGPT 网页） |
| --- | --- |
| 主题解析 → 底稿 → 容量压缩 → 主题核对 → 长视觉 Prompt → 单张图 → 读图核对 → 重画 | 主题解析 → **极简 Prompt** → ChatGPT 自主决定 1~N 张 → **全部取回** → 本地 OCR 独立读图 → 订阅模型知识核对（准确性 / 覆盖度 / 可读性三态）→ 生成“文字版要点” |

- 生图 worker 支持**多张图**：逐张取回“已生成图像 1…N”；若 ChatGPT 回复“要不要继续生成下一张”，自动回复“继续”（上限 6 张、最多 3 轮）。
- 后端个人生图任务支持多图回传（按序号幂等上传），资源卡以画廊展示。
- “可核验生成”继续作为创新点：从“忠实于底稿”升级为“**独立读图 + 知识准确性/覆盖度双维核验**”，不再限制 ChatGPT 的构图发挥。
- 非 ChatGPT 网页路径（API 图像模型 / 小云雀）保留原底稿链路作为备用。

### 3.2 功能联动（点完一个功能，推荐下一步）
每个结果卡底部给 2~3 个“下一步”，依据**资源类型 + 学习状态**生成：
- 讲解视频 → 一图看懂（回顾全局）/ 巩固测验
- 一图看懂 → 记忆歌曲（记住要点）/ 巩固测验 / 讲解视频（过程性内容）
- 记忆歌曲 → 记忆闪卡（主动回忆）/ 巩固测验
- 巩固测验有错 → 易错易混 / 错题本；全对 → 下一个知识点 / 复习 PPT
- 学习笔记 → 记忆闪卡 / 一图看懂
对话区工具建议改为第 2 轮起按问题类型推荐（全局/对比 → 一图看懂；过程/步骤 → 讲解视频；要背 → 记忆歌曲；“懂了” → 巩固测验）。

### 3.3 首次引导
- 首屏改为“今天想学什么？”大输入框 + 跨学科示例 + 内置课程快捷卡；三步导览只出现一次（修复重复弹出）。
- 自定义主题建课**永不阻塞**：起点测评草稿失败也能直接进入课程，测评稍后生成。

## 6. 新功能：音乐化记忆歌曲（「记忆歌曲」）
**流程**：知识要点 → **口诀/顺口溜** → **大模型决定音乐方案**（曲风、BPM、情绪、人声、结构及理由）→ **歌词**（副歌 = 核心口诀反复）→ 歌词知识核对（一次有界修正）→ Suno 专业模式生成（2 个版本，异步受理 + 幂等键）→ 音频/封面转存本地（平台地址 7 天失效）→ 时间轴歌词 → 卡拉 OK 播放 + 跟唱填空 → 口诀进入复习队列。

**曲风决策参考（给模型的依据，不硬编码）**：并列清单/术语密集 → 说唱；步骤/时间顺序 → 叙事民谣/流行；公式/定义 → 洗脑儿歌/电子流行；古诗文/历史 → 国风；英语词汇 → 英文流行/童谣。

**学习科学依据**：旋律与节奏促进文本回忆（Wallace, 1994, *JEP:LMC*）；歌唱促进外语学习（Ludke et al., 2014, *Memory & Cognition*）；GPT + Suno 个性化音乐助记提升计算机概念记忆（KoroT-3E, arXiv 2409.10446）；测试效应（Roediger & Karpicke, 2006）→ 跟唱填空做主动回忆。

## 7. 讲解视频：Claude 生成（最后做）

### 7.1 合规的“订阅接入”方式（重要）
Anthropic 官方条款（Claude Code《Legal and compliance》）明确：**不允许第三方应用提供 Claude.ai 登录、代存或转发订阅凭据**；但**允许用户用自己的订阅登录未修改的官方 Claude Code**。因此不照搬 pi 的网页 OAuth，而是：
- **本机订阅（仅本人本机，已实现）**：启动菜单“登录 Claude”安装官方 `@anthropic-ai/claude-code` 到项目目录，并运行官方 `claude auth login` 在浏览器完成授权；本机 worker 无头调用这个已登录的 CLI 生成视频，网站不接触任何 Claude 凭据。
- **API Key（已实现，按量计费）**：网页里填写 Console Key（`sk-ant-` 开头），加密保存，只在制作时交给本机 worker，并可设置单条视频费用上限。
- 网页「设置 → 讲解视频 · Claude」（仅本机拥有者可见）：本机接入状态（在线 / CLI 版本 / 是否登录 / 工具版本）、模型（Opus 5.5 / Sonnet 5.5 / Fable 5.1）、思考强度（低→最高）、时长上限（60/90/120/180 秒）、中文配音（5 种音色）、画质、“制作前先给我看分镜”、接入方式、测试连接。

### 7.2 视频生成链路（已实现）
1. 媒体智能体照常先产出讲稿与分镜草稿（Kimi / ChatGPT），随后把任务交给 Claude，**生成任务不等待视频**，资源卡上实时显示进度。
2. **分镜**：Claude 只写 `storyboard.json`（提示词 `video.claude_storyboard`，改编自你的视频 Prompt：苹果风高端极简、丝滑转场、画面与知识步骤一一对应、先结论后原因、最小例子、回忆链 + 10 秒自测、准确性红线）。
3. **配音**：worker 用 edge-tts 逐镜录制中文旁白（失败时整片改用 macOS 系统中文语音，不混用），用逐词时间戳对齐短句字幕，按真实配音时长给每一镜定 `start/end`，并做响度标准化。
4. （可选）**确认分镜**：开启后在视频卡片上查看分镜并附画面意见，确认后才开始制作。
5. **制作**：Claude 按 `video.claude_production` 与品牌视觉规范 `video.claude_style`，在独立工作区用 HyperFrames（HTML + GSAP，本机 Chrome 渲染）制作，`hyperframes lint` → 逐镜 `snapshot` 截图自查修正（最多三轮）→ 渲染 1080P。
6. **校验与回传**：worker 用 ffprobe 检查 H.264 / 1920×1080 / 30fps / yuv420p / AAC 音轨 / 时长与配音一致，不通过则让 Claude 按 `video.claude_repair` 修一轮；通过后加 faststart、截取封面，上传成片，网页显示播放器、章节跳转、下载和 Claude 自查说明。
7. **安全边界**：无头运行使用 `dontAsk` 权限模式 + 白名单（只能编辑工作区文件、运行 hyperframes / ffmpeg / ffprobe / 校验命令），禁用网页抓取与搜索、禁用 HyperFrames 的发布/云渲染/预览等联网命令，关闭用户钩子与外部 MCP；资料中的“指令”一律视为待讲解内容。

验证情况：后端 + worker 单元测试（任务队列、租约、取消、重试、审批、上传校验、断句与字幕对齐、权限参数、错误分类）全部通过；用替身 claude 跑通了“领取 → 分镜 → 真实 edge-tts 配音 → 真实 HyperFrames 渲染 → 校验 → 上传 → 网页播放与章节跳转”；用真实官方 Claude Code 2.1.301 验证了全部无头参数可用、未登录时网页给出“请登录 Claude”的提示。**尚未验证：你的 Claude 订阅登录后的真实成片质量**（需要你先在启动菜单“登录 Claude”）。

参考：Code2Video（Planner–Coder–Critic 三智能体代码化教学视频，arXiv 2510.01174）、Mayer 多媒体学习原则。

| 知识追踪 | 标准 BKT，参数固定，无遗忘 | **BKT⁺**：① 证据分级（独立作答=全证据、提示后=部分证据、看答案=无正证据）；② 题型相关猜测率（单选 1/k）；③ 遗忘衰减（按间隔向先验回落，复习越多衰减越慢） | Corbett & Anderson 1994 (*UMUAI*)；Baker et al. 2008 (ITS)；Qiu et al. 2011 (UMAP)；Pardos & Heffernan 2010 (UMAP) |
| 复习调度 | 固定 1/3/7/14/30 天 | **FSRS-6**（项目已依赖 `fsrs`）：错题、闪卡、口诀统一按“记忆稳定性 / 可提取性”调度 | Ye et al., KDD 2022；Ye et al., *IEEE TKDE* 2023；Settles & Meeder, ACL 2016 |
| 学习路径 | 1−掌握度 + 目标 + 易错 + 难度 | **ZPD 目标化打分**：预测答对率 0.6–0.85 优先；可提取性低的已学点插入复习；先修缺口优先 | Clement et al., *JEDM* 2015 (ZPDES)；Bjork 1994；Roediger & Karpicke 2006 |
| 功能推荐 | 无 | 学习闭环状态机 + 可解释规则推荐（3.2 节） | Mayer 2021；KoroT-3E 2024 |

全部为确定性、可解释算法并配单元测试；不使用黑盒神经网络（数据量不足以训练，也不利于答辩解释）。
