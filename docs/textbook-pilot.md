# Python 教材到学习证据的试点

## 本轮解决什么

学生看到教材名称之后，应能知道该读哪一节、做什么练习，以及学习后有没有新的独立作答证据。本轮贯通一个真实来源的四个主题：变量与表达式、条件与分支、循环与列表、函数与返回值。

流程为：注册与目标 → Python 课程范围 → 12 道起点题 → 按表现和可用时间安排计划 → 原文章节与分步讲解 → 独立新题 → 更新计划 → 延迟新题复测。测评全错的学习者先补基础，全对的学习者安排应用与复习；保存学习者的目标、时间、当前课程和教材版本，供后续资料生成读取。

## 实际导入的内容

- 来源：[Python 官方中文教程](https://docs.python.org/zh-cn/3.14/tutorial/)，抓取页面标识版本 `3.14.7`。
- 10 个完整小节：数字、文本、列表、编程第一步、if、for、range、函数定义、默认参数、深入条件控制。
- 正文快照位于 `backend/app/data/textbooks/python_tutorial.json`；保留章节锚点、各节 SHA-256、抓取时间和改编说明。HTML 转换去除导航和标题链接，保留代码块。它不是整本 Python 教程。
- 许可保留于 `PYTHON-LICENSE.txt`，来源 [Python 官方许可页](https://docs.python.org/zh-cn/3.14/license.html)：正文 PSF-2.0，文档示例另适用 0BSD。本站讲义和题目另行编写。
- `backend/scripts/import_python_textbook.py` 可重建快照；导入离线于学习请求执行。更新教材需要重新审核、测试、发布；已建立课程保留旧版原文，避免静默替换学习依据。

## RAG 如何使用

`textbook_service` 将完整章节按段落切分，代码示例不从中间切开，每个片段保留原文字符位置。Python 课程检索其固定版本的章节，经现有向量模型与重排处理。选择仅上传文件时，不混入平台教材；其他课程不混入 Python。当前规模较小，使用现有检索基础设施，没有新增向量数据库。

生成资料保存所用来源、章节、版本、原文预览和原网页链接。页面显示本轮接入范围；每项计划有具体阅读位置。后续模型提示继续使用学习者目标、每日时间和当前课程上下文。

统一来源选择会将默认教材显式传入资料生成、对话和答疑入口，避免非数据结构课程被当作无资料的自定义主题而跳过检索。

## 新题与复测

每主题 9 道程序输出题，分三轮，总计 36 道，与起点题分开。题目的正确输出由 Python 实际执行核对；服务器独立判分，提交前接口不暴露答案。

- 首轮 3 题后等待 1 天，第二轮后等待 3 天，再换另一组题。日程是试点规则，未宣称为个体最优间隔。
- 看了资料或得到提示时单独记录，不增加独立掌握度。
- 重复请求不会重复计分；重开测评也不会再次发放已经计分的同一道题。
- 作答事件进入已有学习证据、画像和计划更新流程，保留起点报告。三道新题独立答对可完成当前学习步骤，后续保持情况由复测继续检查。
- 共 9 题用完后停止，明确提示有限题目不能代表整门课程已经掌握。
- 延迟复测由页面显示到期时间并提供入口；本轮未新增推送通知。

## 从飞书吸收了什么

借鉴的是原文定位、解析和抽取分离、保存来源版本、按真实输入贯通接口并验收的方法，落到章节快照、原文锚点、课程版本、引用与学习闭环上。未复用私人课程代码，未把私人飞书正文加入公共教材库。MinerU、LangExtract、Neo4j 仍是候选方案；当前 HTML 教材试点不需要它们。

## 验证与边界

`backend/tests/test_textbook_pilot.py` 核对完整正文切片、固定来源版本、36 道程序输出、跨课及资料选择隔离、弱/强基础计划差异、提示作答、重复提交、多窗口恢复、跨账号访问、课程版本失效及三轮延迟新题。用可控时钟验证等待规则，不把模拟时间说成真实隔天学习。

`frontend/e2e/textbook-pilot.spec.ts` 经浏览器检查新题、反馈、复测提示、刷新恢复和手机布局。显式启用 `PLAYWRIGHT_REAL_MODE=1` 时，增加真实模型生成：要求非演示模式、实际模型讲解、学习目标和时间传递、引用版本及预览与教材原文一致。测试结果保存在忽略的 Playwright 输出目录，账户和运行产物不提交。

自动化验证用于检查上述工程流程；题目尚未经真实学习者标定，不能据此声称提高了学习成绩。通用上传课程目前仍均匀抽取每份最多 6 个片段，扫描教材、公式及整本高数尚不在本试点内。最终测试数量与生产验收结果以本次交付记录为准。
