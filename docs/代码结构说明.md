# SparkLearn 星火学伴 · 代码结构说明

## 2026-10-15 个人普通 Chat 图片接入

`services/personal_image.py`、`api/personal_image.py` 和 `PersonalImageJob` 提供默认关闭、单账号绑定的持久图片交接；`scripts/personal_chat_image_worker.py` 在本人 Chrome 中生成，复用已授权连接读取当前对话预览中的原图并回传。统一网关负责路由，`one_page_image.py` 与 `StudyArtifactBlocks.tsx` 沿用内容检查和文字版。配置及当前验收边界见 [个人 Chat 图片接入](2026-10-15-personal-chat-image.md)。

`manage_personal_chat_image.ps1` 与 `run_personal_chat_image_background.py` 负责当前 Windows 用户显式启动的后台接入，没有登录或定时触发器；空闲队列的暂时网络中断持续退避等待恢复，间隔最多 60 秒，鉴权失败或已领取任务发送不明时停止。

同日晚间稳定性修复：worker 支持仅针对配对网站的 `site_connection=direct`、分阶段耗时与脱敏网络记录；发送前确认及同一原图上传可有界恢复，UI 发送仍只执行一次。`generation_jobs.execute()` 等待个人图片时只查询交接状态，保留已有事件游标，图片到达或失败后再恢复生成图，避免每 5 秒重放任务和进度重置。

## 2026-10-05 真题词句与复习连接

2026-10-15 阅读词典扩展：`reading_dictionary.py` 从 `reading_dictionary_v1.zip` 按需读取分片，不把约 40 万阅读词条载入六级学习词表。生成器 `scripts/build_reading_dictionary.py` 固定原始哈希、来源、许可、词形和稳定标识；词表外词卡可保存、复习，在“我的生词”显示，`cet6_word_plan.py` 对每日新词与完成数继续限定六级词表。补充词使用外部词典发音入口，不请求不存在的静态 MP3。

2026-10-07 词形修复：`cet6_word_lookup.py` 与 `cet6_word_forms_v1.json` 提供词形到现有词条的映射和歧义候选，生成入口为 `scripts/build_cet6_word_forms.py`；`/word-lookup` 为阅读点词提供精确解析，普通词表查询复用映射。词卡显示原文形式，收藏仍归入原 entry / sense；同句 `surface_forms` 保留多个遇到的形式，兼容旧记录。数据来源、边界和验证见下方功能说明。

2026-10-06 交互更新：`ExamReadingTools` 复用 `StudyDialog` 展示词卡，保留原文位置和当前题内草稿；笔记修改更新同一原句记录。`Cet6Vocabulary` 读取一次性的 `cet6_start=review` 直接开始到期复习，随后使用既有轮次恢复机制。

- `ExamReadingTools.tsx`：在真题清晰文字中点词查义、选择原句并收藏；`exam_sentence.py` 经统一模型网关拆句，检查片段引用并提供理解自查。
- `VocabularyCard.data.queued_at`：收藏后的首次待练，独立于已学轨迹；沿用现有 FSRS 安排后续复习。`WordContexts.tsx` 在词卡中显示原句，翻面后显示笔记和原题链接。
- `ExamAction.used_help`：本轮帮助状态随草稿保存、首次提交冻结；`exam_question` 深链接恢复具体题号。范围与验收见 [真题词句与复习连接](2026-10-05-reading-review-loop.md)。

## 2 一次"生成请求"的完整数据流

前端资源工坊 POST `/api/resources/generate`(经 BFF 透传)→ `api/resources.py` 组装初始 State 并交给 `graph.run_with_events()` → 该函数创建请求级队列、把发射器写入 contextvar、后台执行编排图,同时把队列中的事件逐条 `data: {...}\n\n` 回写 → 图内:profile_agent 更新画像并 emit profile → orchestrator 路由 generate → planner 产出资源计划 → path_agent 重算路径并 emit path → LangGraph 把 doc/mindmap/quiz/media 四节点并发执行,各自 retrieve→生成→校验→emit resource,State 写入经 reducer 合并 → eval_agent 汇总 safety_flags、把资源批量 merge 进 resources 表、emit summary → run_with_events 收到完成哨兵,补发 done → 前端 Chat/工坊把 resource 事件落成卡片,AgentTrace 把 agent_* 事件折叠进遥测状态。

## 3 关键设计约定

LLM 访问只允许经 `llm_complete()/llm_stream()`,新增智能体不得自行创建客户端,这样互备、Mock 与计量在一处生效。所有模型 Prompt 文案统一放在 `app/prompts/`，调用方通过 `invoke_learning_prompt()` 按能力名加载，不在 Python 中维护长 Prompt 字符串；`system.md` 会与对应模块模板一起发送。事件一律通过 `emitter.emit()` 发出,字段以 `type` 区分,新增事件类型需同步更新前端 `lib/types.ts` 与 AgentTrace 的归约逻辑。State 中任何可能被并行节点写入的字段必须带 reducer 注解。JSON 列(payload/citations/safety/data)直接存取 Python dict/list,严禁手工 dumps。资源 `kind` 与生成节点的映射集中在 `graph.py` 的 `_KIND2NODE`。

## 4 扩展指南

新增一个智能体(例如"口述复述检查"):在 `agents/` 写 `async def run(state)->dict`,内部用 emitter 发 agent_start/agent_end;在 `graph.py` 注册节点与边(并行资源类同时加进 `_GEN_NODES` 与 `_KIND2NODE`);如需新资源类型,前端在 `ResourceCard.tsx` 的 KIND_META 与渲染分支各加一项即可。

更换课程:替换 `data/knowledge_graph.json`(节点 id/name/difficulty 与先修边)、清空并放入新课程的 `seed_corpus` 讲义、按需更新 `seed_quiz.json`,前端 `resources/page.tsx` 与 `ProfileRadar.tsx` 的知识点名称映射同步调整;视频链接、网页、案例笔记等补充材料放入 `data/extra_sources`,格式见 `docs/extra_sources_guide.md`。

接入新模型供应商:在 `spark_client.py` 的 MODELS 映射增加角色,或以相同函数签名实现新的客户端文件并在配置中切换。
