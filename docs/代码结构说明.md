## 2 一次"生成请求"的完整数据流

前端资源工坊 POST `/api/resources/generate`(经 BFF 透传)→ `api/resources.py` 组装初始 State 并交给 `graph.run_with_events()` → 该函数创建请求级队列、把发射器写入 contextvar、后台执行编排图,同时把队列中的事件逐条 `data: {...}\n\n` 回写 → 图内:profile_agent 更新画像并 emit profile → orchestrator 路由 generate → planner 产出资源计划 → path_agent 重算路径并 emit path → LangGraph 把 doc/mindmap/quiz/media 四节点并发执行,各自 retrieve→生成→校验→emit resource,State 写入经 reducer 合并 → eval_agent 汇总 safety_flags、把资源批量 merge 进 resources 表、emit summary → run_with_events 收到完成哨兵,补发 done → 前端 Chat/工坊把 resource 事件落成卡片,AgentTrace 把 agent_* 事件折叠进遥测状态。

## 3 关键设计约定

LLM 访问只允许经 `llm_complete()/llm_stream()`,新增智能体不得自行创建客户端,这样互备、Mock 与计量在一处生效。所有模型 Prompt 文案统一放在 `app/prompts/`，调用方通过 `invoke_learning_prompt()` 按能力名加载，不在 Python 中维护长 Prompt 字符串；`system.md` 会与对应模块模板一起发送。事件一律通过 `emitter.emit()` 发出,字段以 `type` 区分,新增事件类型需同步更新前端 `lib/types.ts` 与 AgentTrace 的归约逻辑。State 中任何可能被并行节点写入的字段必须带 reducer 注解。JSON 列(payload/citations/safety/data)直接存取 Python dict/list,严禁手工 dumps。资源 `kind` 与生成节点的映射集中在 `graph.py` 的 `_KIND2NODE`。

## 4 扩展指南

新增一个智能体(例如"口述复述检查"):在 `agents/` 写 `async def run(state)->dict`,内部用 emitter 发 agent_start/agent_end;在 `graph.py` 注册节点与边(并行资源类同时加进 `_GEN_NODES` 与 `_KIND2NODE`);如需新资源类型,前端在 `ResourceCard.tsx` 的 KIND_META 与渲染分支各加一项即可。

更换课程:替换 `data/knowledge_graph.json`(节点 id/name/difficulty 与先修边)、清空并放入新课程的 `seed_corpus` 讲义、按需更新 `seed_quiz.json`,前端 `resources/page.tsx` 与 `ProfileRadar.tsx` 的知识点名称映射同步调整;视频链接、网页、案例笔记等补充材料放入 `data/extra_sources`,格式见 `docs/extra_sources_guide.md`。

接入新模型供应商:在 `spark_client.py` 的 MODELS 映射增加角色,或以相同函数签名实现新的客户端文件并在配置中切换。
