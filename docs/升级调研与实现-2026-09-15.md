# SparkLearn 起点测评、学习计划与界面升级

核验日期：2026-09-15。课程范围：数据结构与算法。本文区分已实现功能、设计参考与尚未验证的能力。

## 实际缺点与本次修正

| 原有问题 | 本次改动 |
| --- | --- |
| 自述直接设置整门课掌握分，选学习方向还加 0.08 | 自述只更新目标、偏好和时间；不覆盖知识证据，也不根据时长推断专注力 |
| “先测水平”只是向聊天发送出 3 题的要求 | 独立服务端题库、判分、存储、暂停续答、重复提交防护与统一解析 |
| 初始计划缺少作答依据、日期和时间预算 | 全面/基础两种摸底，按先修关系、每日分钟、学习日和目标日期生成两周日历；明确列出待安排内容 |
| 资料缺少针对本次错误的整理 | 自动整理具体错题解析、课程讲义与独立练习建议，存入原资源表，可下载 Markdown |
| 网课缺少搜索、预览和外跳路径 | 核验课程资料库筛选、薄弱点推荐、官方播放器按需预览、直达视频与 B 站全站搜索 |
| 导航、题目、长文和卡片均叠加玻璃效果 | 玻璃用于导航和控件；题目与长文使用清晰底色，减少嵌套模糊 |
| 助手提到“看图”“考试”也可能被当成学生偏好 | 只从 user 消息提取明确表达；“认知风格”展示改为自述讲解偏好 |
| 每周 2/3 小时实际保存 140/210 分钟 | 改为 120/180 分钟，并将引导目标与时间带入摸底设置 |
| 示例声称普通二叉树中序遍历必然有序 | 改为二叉搜索树，并比较普通二叉树的适用边界 |
| 字段校验失败时前端对数组调用 slice | 把结构化字段错误转换为可读消息 |

## Apple 官方核验与视觉实现

Apple 将当前材料体系称为 **Liquid Glass**。官方将其用于导航和操作层，要求内容保持清晰、避免过度叠加玻璃。网页实现参考层次、柔和背景、边缘高光、透明和饱和度；不声称复现原生光学折射。

- [Human Interface Guidelines：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
- [Liquid Glass 概览](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass)
- [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)
- [WWDC 2025：Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)

实现位于 `frontend/app/learning-upgrade.css`。保留原三栏工作台结构，新增测评与课程入口；提供可保存的减少透明开关，响应系统减少透明、减少动态效果、提高对比度及强制颜色设置。不支持 backdrop-filter 时使用实色底，不引入 WebGL 截屏依赖。

## 学习科学依据

- **提取练习与分散练习**：先独立回答，再看解析；安排新情境验证和分日复习。[Dunlosky 等，2013](https://pubmed.ncbi.nlm.nih.gov/26173288/)、[Roediger 与 Karpicke，2006](https://pubmed.ncbi.nlm.nih.gov/16507066/)。这些研究支持一般策略，不证明 1/3/7 天对每个学生最优。
- **自我调节学习**：收集目标、时间、学习习惯与支持需求，加入结束反思和可调整计划。[Zimmerman，2002](https://www.tandfonline.com/doi/abs/10.1207/s15430421tip4102_2)。自述指导安排，不给掌握分。
- **信心与正确性分开**：可选记录 25%/60%/90% 信心；答对、不会、跳过分别保存。高信心错误用于复盘，不推断性格或临床状况。
- **不使用固定学习类型匹配假说**：喜欢看图只是偏好，不能推断“视觉型学生学图一定更好”。[Pashler 等，2008](https://journals.sagepub.com/doi/10.1111/j.1539-6053.2009.01038.x)。

## 测评、计划和资料的实际规则

1. 复用原课程客观题，加入 41 道原创补充题，其中 24 道围绕复杂度。全面摸底覆盖 16 个知识点、最多 48 题；基础摸底覆盖复杂度、数组、链表、栈、队列、递归，通常 18 题，跳过时最多 22 题。界面时长为估计，未经样本测定。
2. 覆盖优先，再依前题表现调整难度；复杂度额外平衡渐近量级、循环求和及辅助空间。每个知识点最多收集 3 道未跳过题作初步证据。
3. 不足 3 道显示待补测；有 3 道后按本次正确比例区分优先补基础、需要巩固、本次表现较好。这是描述性教学规则，不是标准化考试、IRT/CAT 或心理量表。
4. 对没有既往练习证据、也没有应用过摸底先验的知识点，使用 `(1 + 答对数) / (2 + 作答数)` 作为初始教学先验，最多 0.75；不会直接标为完全掌握。已有练习结果受到保护。
5. 每次会话固定题库快照与版本；完成前只发送当前题干、选项、知识点，统一完成后公开解析。事务保证答题、资料、画像和路径一起成功或回滚。
6. 重复摸底可能遇到同题，不当作新的独立掌握证据。未测知识点不虚构正确率。还需教师审题、平行题和真实匿名样本标定难度、区分度及猜测效应。
7. 按先修关系排程，未测先修知识阻止直接推进。任务不超过每日容量，休息日不安排，间隔复习不挤在同一天；最低 8 分钟预算也能开始。自述吃力时拆成更小任务。
8. 可以调整日历并保留仍适用的完成记录；勾选进度不会提高掌握分。日历是本次摸底快照，调整时间会重排；已有 BKT、知识关系和复习队列继续工作，日历尚未按所有后续作答自动重算。
9. 资料使用自编课程讲义和本次具体错题，不联网编造教材；表现较好者得到边界核对和迁移建议。缺乏有效作答时不假装生成针对性薄弱点资料。
10. 当前只评估数据结构与算法；高中提前学习和工作后自学也只在本课程范围内判断，不推断其他学科能力。

## 验证与后续工作

运行入口：后端 `.venv/Scripts/python.exe -m pytest -q`；前端 `npm run build`、`npm run test:e2e`。

本地最终检查：257 项后端测试通过；Next.js 生产构建与 TypeScript 检查通过；3 条浏览器流程通过。测试运行于真实 SQLAlchemy/SQLite 和本地前后端；生产 PostgreSQL 与部署后的结果须另行验收。
