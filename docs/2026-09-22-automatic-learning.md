# 学习任务自动选择服务与交互指引

## 本轮需求与决定

学习界面不再显示模型设置、API 密钥或模型方案。用户直接表达学习目标；保留原有 DeepSeek、小云雀、语音和渲染服务，K3 在需要综合分析的任务中自动参与。删除“展开/收起全部工具”与长篇按钮说明，工坊直接显示 11 项生成工具、6 项学习视图和测评/网课入口。

首次进入工作台，通过三步短提示定位提问、学习来源和学习工坊；手机上定位实际可见的底部导航。可以跳过、按 Escape 退出，顶部“学习指引”可重看。是否看过按账户保存在当前浏览器，跨设备不假称同步。正在输入时不再自动打断。

工坊顶部的“小知 · 陪你学”根据资料选择和已完成的问答阶段变换建议。动作直接进入提问、上传、测评或所选生成流程；不会仅因为看到提示而调用付费模型。关闭状态按账户/书本保存，可恢复，并同步同页桌面/手机实例。原有问答后建议的间隔与关闭机制继续生效；轮数不代表掌握程度。

## 调研与复用

2026-09-22 核验了 [Linear 入门指南](https://linear.app/docs/start-guide)、[Driver.js 动态步骤](https://driverjs.com/docs/async-tour)及其 [官方仓库](https://github.com/nilbuild/driver.js)，并对照 [React Joyride](https://github.com/gilbarbara/react-joyride)。Linear 将起步内容按实际任务组织；这里借鉴“给出下一步行动”的方式，不复制页面。

Driver.js 与 Joyride 都能定位控件并分步说明。当前项目已有阶段状态和个性化建议，只缺稳定的定位、键盘关闭、进度与响应式弹层，因此直接使用无运行时依赖的 Driver.js 1.8.0（安装包与仓库许可均为 MIT），保留现有 React 组件与视觉体系。未引入整套 onboarding 平台，也未复制第三方业务源码。此调研用于本项目选型，不声称覆盖所有引导产品或证明学习效果。

## 自动模型选择

- 已有意图/资源流程产生能力名：日常答疑、练习、英语走原 DeepSeek；笔记、研究、教学动画设计、知识图内容走 K3。
- 对话额外参考真实用户请求、选中来源数量和实际检索材料长度。严谨推导、资料对照、长文分析交给 K3；系统提示长度、模型名称和冗长历史不会单独触发升级。
- 规则未识别的请求继续复用原有意图模型调用，在同一 JSON 中补充 `model_depth`。不会为了选择模型给每句话额外增加一次模型调用。
- 简单问题即使出现“复杂网络”或“数学归纳法”也不直接视为复杂任务；否定请求、引用资料中的指令有单独回归样本。该策略仍可能误判，不是跨模型质量基准。
- `KIMI_SMART_ROUTING=true` 且已有两家服务可用时，采用服务端自动策略与原服务端密钥。旧账户方案/个人密钥保留但不干扰自动模式；关闭该开关可恢复旧配置优先级。
- 所有调用仍经 `llm_complete/llm_stream`。实际选择在既有 `progress` 事件的 `model_route` 中记录，前端“依据 → 详细过程”能回看。事件不包含密钥、提示正文或思维链。失败不把模拟回答标记为真实模型结果。

## 验收与边界

本地最终验证：后端 377 项测试通过，前端生产构建通过，7 项浏览器用例通过；桌面 1512×982、手机 390×844 截图已回看。测试不调用真实媒体生成，也不能证明教学效果。

后端回归覆盖语义分类结果传递、简单/复杂任务、否定指令、资料与系统文本边界、旧账户设置兼容及原传输协议。浏览器覆盖首次指引、关闭记忆、主动重看、Escape 与焦点恢复、输入快捷动作、功能完整可达、手机布局，以及原英语/研究/问答建议流程。桌面和手机截图人工回看后，减少了空白聊天页的重复说明，并提高手机工坊背景不透明度。

发布验收必须检查 ECS 部署提交、首页与健康接口，并通过公网真实聊天请求分别观察 DeepSeek 与 K3 的 `model_route` 及非空答案；仅 UI 提示或离线测试不足以证明线上自动选择有效。生产验收记录保存在被 Git 忽略的 `.tmp/automatic-learning/`。图片/视频及语音配置不属于本轮改动，模型选择不表示新增 Kimi-Audio 或 Kimi 视觉识别。
