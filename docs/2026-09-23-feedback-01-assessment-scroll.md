# 用户反馈第一项 测评换题后页面回到顶部

本轮只处理测评页面的位置问题。资料检索、内容串课、音频和其他反馈分别处理，避免把多个原因混在一次修改里。

## 需求与验收

- 提交、跳过或选择“这题还不会”后，当前题干在测评面板的可视区域内。
- 暂停并恢复测评后，保留当前题目并定位到题目区域。
- 完成最后一题后，直接看到测评结果的标题。
- 键盘焦点到达新题或结果标题；整个页面不随面板一起移动。
- 手机往返测评时，对话面板保留离开前的阅读位置。
- 电脑 1440×900、手机视口 390×844 均验证。手机视口测试不等同于所有实体手机浏览器的验收。

## 先复现，再改代码

基线提交为 `b1ac4ed3e9a883f878fd1fafeb225b938c7c5d93`，开始时本地、远端 main 和 ECS 的 deployed_commit 一致。

在基线上新增浏览器回归测试，两种视口均失败。测量发生在点击提交、等待新题出现之后，没有让测试框架先把题干自动滚动进视野。

| 提交第一题后的测量 | 电脑 | 手机 |
| --- | ---: | ---: |
| 修复前面板 scrollTop | 0 | 0 |
| 修复前题干顶端相对面板的位置 | 632.06 px | 744.03 px |
| 面板可视高度 | 792 px | 710 px |
| 修复后面板 scrollTop | 492 px | 561 px |
| 修复后题干顶端相对面板的位置 | 140.06 px | 183.03 px |

手机旧版本的题干整体落在可视区域之外，和用户反馈相符。前端组件 `AssessmentPanel.tsx` 在题目 id、测评状态或设置状态变化时无条件调用 `panel.scrollTo({ top: 0 })`，解释了为什么每次换题都会回到课程说明顶部。

## 修复方法与理由

1. 保留原有的答案、信心与计时重置逻辑。
2. 将 DOM 定位放到 `useLayoutEffect`，根据新题卡片或结果卡片的实际位置计算滚动距离。
3. 只滚动测评面板，使用 `focus({ preventScroll: true })` 设置焦点，避免焦点再滚动其他祖先容器。
4. 没有题目或结果的设置页面才回到顶部。
5. 对话面板往返位置的回归检查通过，因此不改动聊天组件。

不只是删除滚动代码：题目长短不同，如果保留上一题按钮处的位置，下一题题干也可能落在视野上方。修复目标是“定位当前任务”，而不是固定某个旧的像素值。

参考：[MDN 元素滚动](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollTo)、[MDN 焦点与 preventScroll](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/focus)。

## 手动复核

1. 打开测评，滚动到答案区，选择任意答案并提交。
2. 不再主动滑动页面，检查能否直接阅读下一题题干。
3. 分别尝试跳过、不会、暂停并恢复，确认不会退回课程说明顶部。
4. 完成测评，确认结果标题直接可见。
5. 在对话面板滚动到中间，进入测评再返回，确认阅读位置没有丢失。

需要回滚时，对本轮修复提交执行 `git revert`，重新走测试、推送、部署与线上验收；不回退其他任务的提交。
