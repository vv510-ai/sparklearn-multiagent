# SparkLearn AI 辅助开发说明

## 1 使用原则

本项目以讯飞 iFlyCode 作为主要 AI 辅助编码工具，也使用 Codex 等工具进行代码审查、测试补充、文档校对与交付一致性检查。AI 工具只承担辅助工作，不替代团队对需求、架构、算法、数据与最终交付物的责任。

所有 AI 生成或修改的内容均经过人工阅读、按项目边界重构，并以自动化测试、构建检查或人工走查验证。涉及学生画像、掌握度更新、路径推荐、安全过滤与资料引用的关键逻辑，均由团队确认实现与文档表述一致。

## 2 本次交付中的能力状态

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 讯飞星火文本模型 | 已实现 | 统一网关承载问答、生成与推理；编排意图路由规则优先，X2 仅在规则未命中时兜底；其他 grounding / 深度推理按明确的 reasoner 角色调用 X2 |
| 讯飞文生图 | 已实现 | 当前唯一文生图供应商，使用独立文生图凭据并兼容通用讯飞凭据 |
| OpenAI 文生图 | 已移除 | 提交版不包含 OpenAI 生图配置、路由或客户端接口 |
| 讯飞 OCR / TTS | 已实现 | 使用独立视觉/语音凭据并兼容通用讯飞凭据；实际启用取决于部署配置 |
| 小云雀视频 | 已实现、显式调用 | 仅在用户明确请求视频类产物且配置服务凭据时调用；失败时保留本地教学动画与旁白降级 |
| 讯飞内容审核 | 预留 | 当前仅保留设计挂接点，不发起远程审核；已启用版本化本地敏感词表 |

“已实现”表示代码路径与测试存在，不等同于当前部署已配置付费凭据或已在本轮产生新的付费媒体文件。运行时实际状态应以 `/api/health` 与部署环境的非敏感配置检查为准。

## 3 人工复核与可追溯性

- 源码变更通过 Git 提交记录追溯，密钥与个人信息不进入仓库。
- 后端以完整 pytest 回归和 40 问 RAG 验收验证；前端以生产构建与关键页面走查验证。
- Prompt 以独立 Markdown 文件和清单版本管理；当前仅具备版本化、回归与效果记录条件，不宣称已经完成线上对照实验。
- 真人演示视频、账号预置、真实环境截图与提交系统上传必须由团队成员最终人工确认。
