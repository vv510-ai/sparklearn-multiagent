# LearnLoop 学习能力升级与调研记录

核对日期：2026-09-22。本文区分已经实现的行为、外部接口条件与仍缺失的功能。

## 本轮落地

| 需求 | 实现及范围 |
|---|---|
| 按模块选模型 | 账户级设置覆盖讲解、笔记、测验、英语、动画分镜、知识图内容、研究；未覆盖的功能跟随默认模型。支持 DeepSeek、Kimi、OpenAI 官方端点。模型调用仍经过统一网关。 |
| API 设置 | 密码输入框、加密落库、只返回是否配置；基于账户及供应商校验解密。设置版本冲突返回 409，避免两个页面覆盖密钥。个人密钥要求 HTTPS 或本机访问。 |
| 简单易懂而深入的解释 | 飞书“解释”原文已通过授权 API 读取；采用笔记分点、必要的推导中间步骤、术语解释、适用条件、贴切类比、逻辑链、表格及 Mermaid。保留产品的来源引用。 |
| 教学动画 | 按 teaching-animation 修改分镜与 Manim 提示：先明确教学目标，状态变化与旁白一致，保留递归返回过程，要求单步、回退、暂停、变速和重置；提示规范不等于所有生成视频已具备交互控制。 |
| 英语场景 | 影视理解、日常交流、高考、四/六级、考研、雅思、托福、职场目标；读取字幕，浏览器播放本地视频，中英切换、词义搭配辨析及点击练习。字幕台词必须来自原文，回放时间由对应字幕块计算；无字幕时标注原创教学场景。 |
| B站与 YouTube | 双平台筛选、封面、点击加载官方播放器、真实标题、可取得的时长/日期/字幕状态/章节/原站链接。B站为分 P 目录；字幕状态不表示已经获得字幕全文。 |
| 深度研究 | 有界版本：最多 3 个检索词，从 Wikipedia 与 Crossref 收集最多 12 条导言、摘要或题录，记录检索时间、去重、依据可读片段写报告并检查引用编号。未取到全文不能称已读全文；无依据或模型失败时显示受限状态。报告与来源一起保存。 |
| 一图看懂 | 根据指定 Skill 重组概念与机制；密集正文按小节分为最多两张，保留完整文字。生成图失败时显示“资料摘录”，不把固定卡片冒充完整知识图。 |
| 问题引导 | 聊天根据最近问题、回答及选择实时生成后续问题；离线模式明确标注示例。入门问卷及内置基础题固定，自定义课程题由模型生成并校验。 |
| ABCD | 测评本已有点击选项；本轮补充聊天末尾单选题按钮和英语语境题的选择、确认、反馈与重做。 |

## 模型选择依据

以下为根据供应商定位与价格提出的配置建议，并非 LearnLoop 质量排行榜或已完成的跨模型测评。ChatGPT 订阅不包含 OpenAI API 费用。

| 选择 | 建议用途 | 价格/限制 |
|---|---|---|
| DeepSeek V4.1 Flash（deepseek-flash） | 默认经济档、日常提问、词汇与练习 | 非缓存输入约 $0.15–0.30、输出 $0.60–1.20 / 百万 token，峰谷不同 |
| DeepSeek V4 Pro | 中文深入解释、资料整合 | 非缓存输入约 $0.66–1.32、输出 $1.98–3.96 / 百万 token |
| Kimi K3 | 长材料整合、研究、复杂分镜 | 官方充值与权限要求；始终思考，使用其 max_completion_tokens 协议 |
| GPT-5.6 Terra | 英文与结构化笔记的均衡选项 | 按官方实时价格；走 Responses API |
| GPT-6 Astra | 复杂推理与跨学科综合的高能力选项 | 非缓存输入 $10、输出 $50 / 百万 token；费用高不保证每题更优 |

官方依据：[DeepSeek 定价](https://api-docs.deepseek.com/quick_start/pricing/)、[Kimi K3 接口](https://platform.kimi.com/docs/guide/kimi-k3-quickstart)、[OpenAI 模型目录](https://developers.openai.com/api/docs/models)。文本模型选择用于动画/知识图的内容设计，图像生成、音视频合成仍有各自的服务配置。

真实调用边界：本机已有 OpenAI 配置的 GPT-6 Astra 实测返回 HTTP 429 额度不足，未作为业务成功证据；未提供可用 Kimi API Key 时不能称 Kimi 产品接口已实测成功。Kimi Code 的审查授权是另一套能力，不等于应用拥有 Kimi API 额度。

## 与 NotebookLM 对照

按用户所说“notebook kilm”理解为 NotebookLM。Google 当前帮助页已跳转到 Gemini Notebook；对照的是官方已描述功能，未进行盲评或大规模教学效果实验。

| 维度 | 官方产品已有能力 | LearnLoop 本轮的位置 |
|---|---|---|
| 来源驱动学习 | 多类型导入、引用问答、笔记、导图、报告 | 已有资料检索与引用；本轮强化解释方式、字幕来源和研究状态，不能因此声称引用准确率更高 |
| 学习产物 | 音频/视频概览、闪卡/测验、信息图、幻灯片 | 已有对应产物入口；本轮修知识图分图与动画提示，仍缺少成熟的多主持人播客体验 |
| Deep Research | 联网研究、报告、选择导入来源 | 本轮仅有限公开源检索；仍缺通用搜索商、全文阅读、迭代补搜、用户选择后入库与后台可恢复长任务 |
| 学习闭环 | 问答与测验等学习工具 | 现有起点测评、错因复盘、补救及独立复测可与新引导结合，是产品差异化方向；尚无对比实验支持“效果优于” |
| 个性化与国内使用 | Google 模型与生态 | 账户级国产/海外模型选择、B站+YouTube、中文提示模板可单独维护，适合本项目目标用户 |
| 协作与移动 | 共享笔记本、移动应用、生态导入 | 仍缺成熟协作权限、移动离线、外部来源自动同步；保留为后续工作，不伪装已完成 |

## 提示词维护

主业务模板在 `backend/app/prompts/` 按功能分别维护为 Markdown，由 `manifest.json` 登记能力与版本。`shared/explanation-style.md` 统一解释要求；`english/scene.md`、`media/video-script.md`、`media/manim.md`、`doc/one-page.md`、`image/one-page-visual.md`、`research/*.md` 与 `tutor/next-step.md` 分别负责场景。Python 负责注入资料、选择模板及约束，不需要把所有功能写在一个 Prompt 中。

飞书读取了“解释”正文；凭据没有写进代码或记录。ChatGPT 分享页无法直接读取，但已通过任务工具找到并阅读同名任务“调研影视背单词项目与墨墨提取”，采用其中的字幕时间定位、保留语境与原句来源思路。当前没有自动搜索全网影视并切片的素材库，也没有导入墨墨网友助记库。

## 审查与验证记录

KimiBridge 当前没有可调用的服务，使用仓库 `tools/kimi_review_bridge.py` 对接已安装 Kimi Code，发送限定文件的无密钥审查包。两轮有效审查发现并修复：设置保存竞态、字幕与时间戳错配、代理头信任边界、空研究计划、检索词类型异常、加粗选项答案识别、未完成对话配对及无空行字幕。相关依赖中的账户过滤、错误白名单和代理配置由主审复核。另修复“hesitate 怎么用”被误判为软件帮助的问题。

合并远端多课程、Python 及六级测评改动后，前端生产构建及 7 项 Playwright 回归通过。上线验收又发现“用学习笔记解释”被误当成生成独立笔记，已补充路由修复和回归用例。最终后端测试与生产版本见任务交付说明。

真实 HTTPS 验收：DeepSeek Flash 连接成功；用户字幕生成 3 句原文笔记，保留对应时间戳，网页点击作答与窄屏检查通过；研究获得 6 条 Crossref 来源、3 条可读摘要并生成引用报告。Wikipedia 当次不可达，已在结果中公开说明。公网证书校验、HTTP 308 跳转、安全 Cookie 与证书续期任务成功。离线测试、浏览器响应夹具和真实模型请求互不替代。
