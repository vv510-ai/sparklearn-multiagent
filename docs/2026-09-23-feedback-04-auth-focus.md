# 反馈 04：注册、登录输入框的双重错位边框

## 原始反馈与复现

用户 Word 文档第 3 张截图问“这个框违和吗，还是特意设计的？”。称呼输入框外侧有一个完整边框，文字输入区域又多出一个从图标右侧开始的绿色框。

在生产版本 `2565e3b` 的隔离浏览器里点击“创建账户”→“称呼”，复现同样现象。浏览器计算样式显示：input 自身有 `2px` 绿色 outline、`2px` offset；外层 span 同时有绿色 border 和 ring。两个轮廓属于不同元素，尺寸和起点不一致。

根因是全站 `:focus-visible` 规则覆盖了输入框原有的 `outline-none`，与复合输入框的 `focus-within` 样式叠加。文本输入框即使由鼠标点击，也可能需要持续显示焦点；不能假定 `:focus-visible` 只在 Tab 键操作时生效。参见 [MDN focus-visible](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:focus-visible)。

## 修改

- 给称呼、邮箱、密码三种复合输入框标记 `auth-input-shell`。
- 用容器的 `:focus-within` 绘制覆盖图标与输入区域的统一高亮；子元素获得焦点时容器匹配该选择器，参见 [MDN focus-within](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:focus-within)。
- 仅取消这些容器内部 input 的重复 outline。密码显示按钮和其他控件仍保留独立的全站键盘焦点。
- 高对比度模式使用系统 Highlight 色。没有删除全站焦点规则，也没有修改注册或登录逻辑。

## 验证与证据边界

这是局部样式修复，采用真实浏览器检查和前端生产构建，不增加重复样式实现的单元测试。

1. 保存旧版电脑、手机截图和计算样式。
2. 前端 `npm run build` 通过，包括 TypeScript。
3. 本地预览服务启动被执行工具的自动审批规则拦截，工具没有给出更具体原因。因此在隔离浏览器临时加载本轮样式，检查视觉、键盘与高对比度状态。这是预览证据，不当作已部署页面。
4. 提交部署后，使用没有样式注入的新浏览器上下文检查真正的生产页面；电脑 1440×1000、手机尺寸 390×844，检查称呼/邮箱/密码、Tab 焦点、显示密码、高对比度以及横向溢出。
5. 使用独立验收账号，通过真实表单注册、清除该测试浏览器的 Cookie，再通过真实表单登录。生产首页、健康检查及部署 SHA 单独核对。

本机证据在 `.tmp/feedback-04/`：`before` 是旧版，`preview` 是临时样式预览，`production` 是正式部署后的无注入验收。最终结果以 `verification.md` 为准。手机尺寸检查不等于已经覆盖真实 iOS/Android 设备。

## 自己复核

用无痕窗口打开生产网站 → 创建账户 → 点击“称呼”：整个输入区域应该出现一圈贴合外框的绿色高亮，图标右侧不再出现错位内框。

连续按 Tab：焦点依次到邮箱、密码、显示密码按钮；每个位置都应能看出当前焦点。按空格应能切换密码显示状态。

本次工程要点：先找到实际绘制边框的元素，再统一焦点样式的责任；修复视觉问题时，也要验证键盘可用性。
