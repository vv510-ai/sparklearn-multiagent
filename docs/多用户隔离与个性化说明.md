# SparkLearn 多用户隔离与个性化说明

## 数据基座

- 正式环境使用 PostgreSQL；本地开发可回退到 SQLite。
- 登录令牌中的 `sub` 是唯一用户 ID。前端 BFF 会覆盖请求中的 `user_id`，后端仍会再次校验。
- `profiles`、`resources`、对话、路径、事件、测验、复习、资产、外部任务和个性化决策表都启用 PostgreSQL Row Level Security（RLS）。
- 每个数据库事务都会写入 `app.current_user_id`；RLS 同时限制读取和写入。没有用户上下文时默认拒绝。
- 所有业务表的 `user_id` 都引用 `users.id`，删除账号时可级联清理数据。

## 文件、调试记录和视频任务

- `/static/gen/*` 不再是“登录后全部可读”，而是先查询 `user_assets` 所有权；非拥有者返回 404。
- 视频供应商的异步 `task_id` 记录在 `external_tasks`，轮询接口只接受拥有者。
- 调试包读取时校验 `state.summary.json` 中的 `user_id`。
- 可配置 S3 兼容存储，将上传资料和生成文件备份到 `users/{user_id}/...`。支持 AWS S3、Cloudflare R2、MinIO 和提供 S3 API 的存储服务。

正式环境建议配置：

```dotenv
OBJECT_STORAGE_ENDPOINT=
OBJECT_STORAGE_BUCKET=
OBJECT_STORAGE_ACCESS_KEY=
OBJECT_STORAGE_SECRET_KEY=
OBJECT_STORAGE_REGION=auto
```

这些变量留空时仍可本地运行，但 Render 之类的临时文件系统在重建实例后不会保留上传资料和生成文件，因此不能把“持久保存”当作已保证。

## 向量检索隔离

- 每个上传资料切片都携带 `user_id`。
- 内存向量库在相似度打分前按租户过滤，不会先召回再删除。
- Milvus 查询使用服务端过滤表达式限制 `user_id` 和 `source_id`。
- 未提供用户上下文时只能检索系统内置、无所有者的课程资料；上传资料默认关闭。
- 相同文件允许不同用户各自上传、各自索引；重复检测只在同一用户内部生效。

## 个性化如何形成

学习路径不是只读用户姓名，而是读取该用户的掌握度、难度偏好、易错标签和知识图谱先修关系。每次路径生成都会写入 `personalization_decisions`：

- 输入证据：画像版本、知识点掌握度、难度偏好、易错标签；
- 输出结果：下一知识点、候选排序、生成方式；
- 原因：被选知识点的可解释推荐理由。

`GET /api/path/decisions` 可读取当前用户自己的决策记录。它能证明系统确实使用了不同用户的数据，但不能单靠代码保证学习效果一定更好；效果仍需用完成率、延迟复测掌握度、错题复发率等指标做真实对照评估。

## 验证范围

自动化测试覆盖：真实注册与登录、跨用户请求参数、生成文件、视频任务、调试记录、相同资料的多用户上传、向量租户过滤，以及 PostgreSQL RLS 策略生成。
