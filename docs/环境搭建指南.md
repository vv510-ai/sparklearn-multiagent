# SparkLearn 星火学伴 · 环境搭建指南

## 1 准备工作

### 1.1 软硬件要求

任意能运行 Docker 的 x86_64 / ARM64 机器即可,建议 4 核 8G 以上;本地开发方式需要 Python 3.10+ 与 Node.js 24 LTS（Next.js 16 的最低要求为 Node.js 20.9）。系统不依赖 GPU(BGE-M3 本地向量化为可选项,CPU 亦可运行)。

### 1.2 文本主脑与讯飞多模态密钥

文本主脑由部署配置决定：`LLM_PROVIDER=auto` 时，存在 `DEEPSEEK_API_KEY` 就先使用 DeepSeek；否则使用星火。DeepSeek 调用失败且配置了 `SPARK_API_PASSWORD` 时，也会继续降级到星火。2026-08-01 的生产 `/api/health` 实测为讯飞星火 X2。讯飞 APPID、APIKey、APISecret 三元组独立用于 TTS、文生图、OCR 等多模态能力。

把真实凭据只填入项目根目录 `.env`，不要提交：

```
LLM_PROVIDER=auto
DEEPSEEK_API_KEY=你的DeepSeek密钥
SPARK_API_PASSWORD=你的APIPassword
SPARK_APPID=xxxx
SPARK_API_KEY=xxxx
SPARK_API_SECRET=xxxx
```

如需星火文本互备，在讯飞开放平台开通 4.0 Ultra、X2 与 Lite；X2 使用独立 `/x2/` 路径。文生图提交版只使用讯飞，建议为 `SPARK_TTI_*` 配置独立应用凭据。

### 1.3 小云雀视频生成(可选)

登录小云雀网页版,从顶部「CLI/API → API」新建 Access Key。填入 `.env`:

```
XYQ_ACCESS_KEY=你的小云雀AccessKey
XYQ_VIDEO_MODEL=Seedance_2.0_mini_lite
```

不配置时,媒体智能体自动降级为"Manim 动画代码 + 讯飞 TTS 旁白",视频功能仍可演示。

### 1.4 关于离线演示模式

`.env` 中 `DEEPSEEK_API_KEY` 与 `SPARK_API_PASSWORD` 都留空,或显式设置 `DEMO_MODE=true`,系统即进入离线演示模式:全部文本大模型调用由内置 MockEngine 以流式方式模拟,五大功能完整可走,内容明确标注为演示数据。该模式专为评审现场断网、密钥配额耗尽等情况兜底。

## 2 部署方式一:Docker 一键启动(推荐)

```bash
git clone <仓库地址> sparklearn && cd sparklearn
cp .env.example .env          # 按 1.2/1.3 填写；文本密钥均留空则走演示模式
docker compose up -d --build
```

启动完成后访问:前端 http://localhost:3000,后端 Swagger 文档 http://localhost:8000/docs,健康检查 http://localhost:8000/api/health(其中 `demo_mode` 字段可确认当前模式)。

如需启用 Milvus 向量库(默认用内存向量存储即可演示):

```bash
docker compose --profile vector up -d
# 然后在 .env 中设置 MILVUS_URI=http://milvus:19530 并重启 backend
```

## 3 部署方式二:本地开发

### 3.1 后端

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

启动日志会输出语料入库的 chunk 数与当前 demo_mode。若需本地 BGE-M3 向量化与重排,请额外安装可选依赖(requirements.txt 中注释行):`pip install FlagEmbedding pymilvus`。

### 3.2 前端

```bash
cd frontend
npm install                   # 国内可加 --registry=https://registry.npmmirror.com
cp .env.local.example .env.local   # 默认指向 http://localhost:8000
npm run dev                   # http://localhost:3000
```

### 3.3 运行测试

```bash
cd backend
python tests/test_services.py     # 服务层单元测试
python tests/test_e2e_graph.py    # 端到端三链路冒烟(演示模式)
```

## 4 知识库语料维护

教材语料位于 `backend/app/data/seed_corpus/`,为带 front matter 的 Markdown:

```
---
source: 《数据结构与算法》讲义
chapter: 第6章 树与二叉树
kp: binary_tree,bst
license: 自编开源讲义(CC BY-SA 4.0)
---
正文……
```

新增或修改文件后重启后端即可自动重新入库(幂等)。若原始资料是 PDF/PPT,建议先用 PyMuPDF 或 Unstructured 转成上述 Markdown 再放入目录。题库种子位于 `backend/app/data/seed_quiz.json`,知识图谱位于 `backend/app/data/knowledge_graph.json`,三者均可由教研侧直接编辑。

## 5 常见问题排错

后端 8000 端口起不来:多为依赖未装全,确认在 backend 目录执行过 `pip install -r requirements.txt`;Python 低于 3.10 会在类型标注处报语法错误。

前端能开页面但对话无响应:检查 `frontend/.env.local` 的 `BACKEND_URL` 是否指向后端;docker-compose 内部应为 `http://backend:8000`。BFF 仍兼容旧变量 `NEXT_PUBLIC_BACKEND_URL`,但新部署应使用仅服务端可见的 `BACKEND_URL`。浏览器控制台若见 502,通常是后端未就绪。

SSE 卡住不出字:经 Nginx 反代时需关闭缓冲(`proxy_buffering off;`),本项目响应头已带 `X-Accel-Buffering: no`,自建网关请保留该头。

星火接口 401/11200:APIPassword 填错或档位未开通;X2 深度推理走独立 base_url(…/x2/),不要与 /v1/ 混用。429 限流时系统会自动向 Ultra→Max→Pro→Lite 互备,日志中可见切换记录。

思维导图/流程图不渲染:这两类经 CDN 加载(cdnjs/jsdelivr),内网环境不可达时会自动降级为源码文本,属预期行为;如需内网渲染,可把对应脚本下载到 `frontend/public` 并修改 `lib/cdn.ts` 的地址。

Milvus 启动后连接失败:确认 `--profile vector` 已带起 etcd 与 minio,且 `MILVUS_URI` 在容器网络内为 `http://milvus:19530`;不配置 Milvus 时系统使用内存向量库,功能等价,数据持久化在 `backend/app/data/vector_store.json`。

数据想重置:删除 `backend/sparklearn.db`(SQLite)或重建 PostgreSQL 卷 `docker compose down -v && docker compose up -d`。
