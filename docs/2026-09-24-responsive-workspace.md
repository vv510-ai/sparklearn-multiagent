# LearnLoop 多端学习体验改造

## 范围

针对手机阅读区域被多层标题、卡片和输入工具挤压的问题，调整现有学习工作台；不替换技术栈、不改模型路由或评分规则。

| 场景 | 本轮实现 |
| --- | --- |
| 手机与窄屏 | 单栏阅读；课程标题常驻，次要操作收入菜单，来源与工坊按需打开 |
| 900–1399px | 来源与学习区双栏；工坊按需展开 |
| 1400px 及以上 | 三栏工作台；来源、工坊均可收起，来源栏支持拖动与键盘调宽 |
| 对话输入 | 独占整行，至少两行，随内容增高；附件、语音、展开、发送位于下方工具栏 |
| 长答案 | 全屏编辑消息；练习进入单题专注模式，简答题使用大文本区 |
| 题目导航 | 上一题、下一题和题目选择；切题回到题干并移动焦点，关闭后回到原入口 |
| 键盘与触屏 | 根据 VisualViewport 调整可见高度；输入时收起底栏，触屏回车换行，兼容中文组合输入 |
| 草稿 | 按账号、课程、对话或题组隔离；刷新恢复；发送失败保留原文；同题组不同入口同步提示记录 |
| 继续学习 | 登录恢复有效的最近课程；旧测评记录不能覆盖最后选择的课程；过期或退出时清理旧账号界面状态 |
| 网络依赖 | 移除阻塞页面的 Google Fonts CSS 导入，使用系统字体；公式字体仍由应用本地提供 |

草稿仅存当前浏览器，最长恢复窗口 30 天。它不是云端草稿同步。已经保存的课程、对话和评分继续使用现有服务端接口；本轮没有把未提交草稿上传到服务端。

## 自动验收

相关文件：`frontend/e2e/responsive-workspace.spec.ts`。

1. 十种窗口：360×800、390×844、430×932、768×1024、900×720、1024×768、1280×800、1440×900、1920×1080、640×420。检查页面不横向溢出、输入框与发送按钮完整可见；检查双栏、侧栏收起及宽度调节。
2. 长文展开、中文输入、关闭、刷新、模拟 503 后恢复，以及课程间草稿隔离。
3. 专注作答、切题焦点、关闭返回、归档与对话共享草稿/提示状态、真实评分接口提交和刷新后的复盘恢复。
4. 模拟 VisualViewport 缩短，验证发送区与导航收起/恢复。
5. 两个独立浏览器上下文登录同账号：已保存课程与对话恢复，本地未发送草稿不串到另一浏览器。
6. 注入旧测评恢复信息，验证最后主动选择的课程优先。
7. 触屏浏览器模拟下，回车产生换行而非发送。
8. 模拟 401 后在同页登录另一账号，验证旧课程、旧消息和草稿不残留。

回归还包括手机/电脑测评滚动、返回对话保持阅读位置、生成进度状态，以及数学公式渲染与溢出。

本轮本地结果：接入最新主分支后生产构建与 TypeScript 检查通过，后端 **463 passed**，生产构建上的相关浏览器回归 **22 passed**（其中本轮多端用例 8 项，另有测评、公式、生成进度及来源引用回归）。截图已逐项检查手机、平板、电脑及长文/作答界面。

本地运行示例：

```powershell
# 已启动测试用前后端时
$env:PLAYWRIGHT_BASE_URL='http://localhost:13000'
npx playwright test e2e/responsive-workspace.spec.ts e2e/math-rendering.spec.ts e2e/generation-progress.spec.ts e2e/assessment-scroll.spec.ts e2e/citation-rendering.spec.ts
npm run build
```

本地浏览器测试使用离线 Demo 引擎及独立测试账号，不证明真实模型质量。503、401、旧测评状态、长消息滚动和资源卡片展示使用明确的传输测试夹具；资源持久化、提示请求、评分、登录与课程接口由本地后端实际执行。生产验收单独记录，不能用这些夹具代替。

## 人工复核

1. 手机打开学习对话，输入多行回答并点击展开，确认不必在狭窄的一行里编辑。
2. 打开练习并进入专注作答，写简答、切题、返回对话，再回到题组确认草稿仍在。
3. 在平板横屏打开资料栏并调宽；在电脑分别收起左右栏。
4. 换浏览器登录同账号，检查已经保存的课程和对话。

真实 iOS Safari、Android 系统键盘、微信内置浏览器、系统大字体及软键盘候选栏仍需对应真机复核。浏览器模拟的尺寸、触屏与视口 API 验收不等同于真机测试。本轮不承诺离线发送或跨设备未提交草稿同步。
