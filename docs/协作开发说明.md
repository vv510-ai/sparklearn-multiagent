# SparkLearn 协作开发说明

这份文档给两个人或多个人协作时使用。核心原则是：不要所有人都直接改主目录，不要先写代码再猜接口。

## 先看这四份文档

```text
docs/api_contract.md
```

前后端接口契约。任何人改接口、SSE 事件、资源 payload、视频字段、评估字段前，都先看这份。

```text
docs/trace_debug_runbook.md
```

中间产物 trace 调试手册。效果差、资源没显示、视频不播放、画像没更新时，按这份文档查。

```text
docs/extra_sources_guide.md
```

多来源 RAG 资料接入指南。要把视频链接、网页、案例笔记、转写文本加入知识库时，按这份文档放文件。

```text
docs/代码结构说明.md
```

项目目录和模块说明。

```text
docs/测试说明书.md
```

后端和前端测试方式。

## 接口改动规则

只要涉及下面任何一项，都先改 `docs/api_contract.md`：

```text
1. 新增 API
2. 修改请求 JSON
3. 修改返回 JSON
4. 修改 SSE 事件 type 或字段
5. 修改 ResourceItem payload
6. 修改 video.url / task_id / status
7. 修改 quiz question 字段
8. 修改 profile/path/eval 报告字段
```

接口改动顺序：

```text
先改 docs/api_contract.md
再改 backend
再改 frontend/lib/types.ts
最后改页面组件
```

不要让前端猜后端字段。

## 启动后端

第一次进入新的 worktree 后，需要自己建 Python 环境并安装依赖：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

后端地址：

```text
http://127.0.0.1:8000/docs
```

健康检查：

```text
http://127.0.0.1:8000/api/health
```

## 启动前端

第一次进入新的 worktree 后，需要安装依赖：

```powershell
cd frontend
npm install
npm run dev
```

前端地址：

```text
http://127.0.0.1:3000
```

前端会通过下面这个代理把 `/api/*` 转发到后端：

```text
frontend/app/api/[...path]/route.ts
```

## 中间产物在哪里

每次后端跑资源生成，都会自动写入：

```text
backend/runs/{session_id}/
```

重点看：

```text
request.json
events.jsonl
profile.output.json
planner.output.json
path.output.json
resources/
agent_end/
eval.output.json
final_state.json
summary.json
```

这些文件不要提交到 git，它们已经被 `.gitignore` 忽略。

## 调试顺序

如果页面没有反应，按这个顺序查：

```text
1. 后端健康检查是否 200
2. 前端页面是否 200
3. 浏览器 Network 里 /api 请求是否报错
4. SSE 事件里有没有 error
5. SSE 最后有没有 done
6. backend/runs/{session_id}/ 里中间产物是否完整
```

如果资源生成了但页面不显示，查：

```text
1. SSE 是否收到 resource
2. resource.kind 是否合法
3. resource.payload 是否符合 docs/api_contract.md
4. frontend/lib/types.ts 是否同步
5. ResourceCard 是否支持这个 kind
```

## 提交自己的修改

只提交自己负责的文件：

```powershell
git status
git add 你改过的文件
git commit -m "feat: 简短说明你做了什么"
```

不要随便用：

```powershell
git add .
```

除非你非常确认没有混入临时文件、数据库、运行日志、`.next`、`node_modules`。
