# 反馈 03：一图看懂的英文、符号和编号失真

## 问题与证据

上一轮实际生成的六级知识图出现重复步骤③、英文拼写错误，以及“不等于”被画为“等于”。正文正确、图片已加载，并不能证明图片内容正确。生产旧资源 `1935d8310188` 及 `.tmp/feedback-02/production/original-image-view.png` 是本次基线。

先增加两个可控回归：要求知识图保留原始字符；要求未通过事实核验的 `promising = proven` 不进入最终内容。修复前二者均失败，旧逻辑仍调用生图模型，核验失败也只追加提醒。

## 修改与取舍

1. 文本模型继续通过现有统一网关整理有引用的短文，保留当前课程、用户和资料范围。
2. 资料一致性检查失败、不可用或扩写生成失败时，改为完整的本次检索片段，标记 `source_excerpt`。原文摘录不是对整份资料的总结，也不冒充扩写核验通过。
3. `one_page_renderer.py` 用固定 SVG 图形和转义后的文字排版；英文、符号和编号不经过图片模型。文本过长时分卡、分图，不缩略或截断条件。没有课程证据的通用知识明确标记未核验。
4. 保存渲染器版本、正文 SHA-256 和每页可见文字 SHA-256。哈希用于核对底稿和输出的一致性，不证明事实为真。SVG 仅有固定 svg/title/rect/g/text 节点，没有脚本、外部图片或可执行用户标签，仍受既有资源归属权限保护。
5. 历史 AI 配图保留，但默认折叠并提示文字、编号和符号可能失真；新生成的资料摘录明确说明范围。排版失败仍保留文字和出处，不宣称图片成功。
6. 首次生产复核发现语义核验漏过“每天 20 分钟”这个无来源标题。增加标题与正文的数字时长检查：有资料范围时，未在片段出现的时长触发原文摘录。该检查是针对时长的保守补充，不代表能证明所有语义事实。

这项取舍牺牲自由插画布局，换取文字可核对和可放大。图的正文仍需核对来源；本次没有实现公式语义证明或对所有模型输出的绝对正确保证。

SVG 的文本元素由浏览器绘制，换行由本项目计算；参考 [MDN SVG text](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/text)。浏览器验收会进一步检查真实字体边界，不能只信字符宽度估算。

## 验证方式

- 后端 `tests/test_one_page_text_integrity.py`：字符保留、被拒绝的结论替换、长文本分页无丢失、SVG 注入文本转义、排版失败、通用知识不冒充资料核验；旧多媒体测试同步验证不再依赖图片服务。
- 后端全量 pytest 使用新的独立 SQLite 数据库，不修改开发数据库。
- 前端生产构建检查 TypeScript 与 Next.js。
- `frontend/e2e/one-page-feedback.spec.ts`：真实注册账号、准备六级课程、提问、点工坊、读取持久化结果；检查 SVG 加载、正文与图中文字哈希、字体边界、原图截图，另测资料不足分支和资源访问隔离。
- 本地离线浏览器验证只能证明链路；部署后在阿里云生产地址运行同一测试，使用真实文本模型，不拦截或伪造生成接口。历史配图另在原测试账号中检查折叠和提醒。

本轮日志、截图、SVG 和证据 JSON 在 `.tmp/feedback-03/`。线上完成状态以生产测试日志、部署 SHA 和本轮交付记录为准。

## 自己复核

1. 刷新生产网站，进入大学英语六级，提问“选词有没有记忆点”，待回答完成后点“一图看懂”。
2. 展开图卡，点图放大。对照下方“查看文字版与出处”，检查英文、否定、符号和步骤。若显示“仅展示相关资料原文摘录”，说明扩写没有通过检查。
3. 打开旧图，应先看到失真提醒，主动展开后才显示旧图片。
4. 在该课程问“量子纠缠有没有记忆点”，再生成：应提示未生成，没有错误说明组成的假知识图。

这次练习的工程方法：现象与底稿对照 → 写出失败断言 → 将文字绘制交给确定性代码 → 验证正常、降级、失败路径 → 部署后重走真实用户流程。
