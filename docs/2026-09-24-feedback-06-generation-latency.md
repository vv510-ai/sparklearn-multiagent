# 反馈 06：互动讲解等待过久

## 现象与证据

用户反馈文档第 15 段对应 image6.png：点击“把刚才讨论的内容做成互动讲解”后，小知回答长时间空白。

2026-09-24，在生产版本 b774c60cc51fe8cbfe186bfe3f60ad9ce227d671，用独立验收账号学习函数极限后点击“互动讲解”，记录浏览器收到的真实 SSE：

| --- | ---: |
| 收到响应头 | 0.150 秒 |
| 进入文档生成 | 0.201 秒 |
| 云端语音完成 | 15.402 秒 |
| 装饰封面完成、讲解卡片到达 | 92.625 秒 |
| 完成并落库 | 92.710 秒 |

请求发出 1.2 秒后，对话区正文仍为空。主要额外等待来自装饰封面：语音已经可用，`asyncio.gather(tts, text_to_image)` 仍等图片才发出 resource。

## 修复

- 互动讲解只生成讲稿和语音，取消该模板的装饰封面请求。其他图文模板保持原有封面功能。
- 点击后立即显示准备状态。后端在正文整理、内容检查、语音生成前分别发出现有 progress 事件；聊天和过程面板展示这些真实阶段。
- 进度独立于正文；收到正文或卡片、完成、停止、错误时退出等待显示。内部供应商错误与遥测字段不直接塞入学习正文。
- 保留模型网关、正文内容校验、来源限制、原有语音提供商选择与失败处理。没有缩短超时来掩盖失败，没有用 Mock 作为线上验收。

## 自动检查与复测

1. 后端测试让封面服务永不返回，验证互动讲解仍可返回真实契约的语音结果；旧实现会超时。
2. 验证阶段事件先于对应工作，正文经过检查后才开始语音；旧实现缺少阶段事件。
3. 浏览器用可控 SSE 验证立即反馈、阶段切换、完成、停止和错误恢复。该测试只证明界面状态，不证明真实模型速度。
4. 完整后端测试使用独立临时 SQLite 数据库；避免已有本地旧表结构影响验证。前端使用 `npm run build -- --webpack` 完成构建和类型检查。
5. 发布后在同一验收账号复测相同入口，检查 SSE 时间、实际音频播放与保存后的资源。线上结果及版本记录在 `.tmp/feedback-06/verification.md`；原始数据为 `before/events.json` 与 `after/events.json`。

本轮隔离验证结果：完整后端 **444 passed**（48.64 秒），前端构建与 TypeScript 检查通过，浏览器状态回归 **1 passed**（55.5 秒，覆盖多种状态）。

## 手工验收

1. 打开生产网站，在高数课程中讨论一个具体的极限例子。
2. 点击“互动讲解”：立即看到准备状态，随后看到正文整理、内容检查或语音生成状态；短阶段可能快速切过。
3. 等讲解卡片出现，展开并播放，确认有声音、时长和播放进度。
4. 再生成一次并点停止，确认等待状态消失，可以继续输入。

## 学到的工程方法

把请求响应、首个可见反馈、可用内容和最终完成分开计时。沿事件时间线找到卡住用户的依赖，再做最小改动。先用失败测试固定问题，再用真实线上链路核验。单次前后耗时属于样本，不能承诺所有模型请求都固定在同样秒数完成。
