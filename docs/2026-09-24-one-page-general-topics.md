# 一图看懂：通用主题修复与验收边界

## 原问题与复盘

用户在高数整体框架请求中收到“跑题、资料导读、未生成”的组合提示，没有看到小云雀图片。该提示发生在知识底稿阶段，不能据此归因于小云雀 API 未接入。此前六级资料正例验证了部分链路，却没有验证无资料课程、简称、跨课程与资料边界的组合；上轮完成结论超出了当时证据。

本次用固定原创样本复现四类正确底稿误拒：高数/高等数学、物理学/大学物理、English Grammar/英语语法、CS/计算机科学。修复前四例及“旧二叉树知识点→新有机化学请求”共五例失败。没有读取用户生产数据库里的原始回答，不能声称已重现截图当时模型的具体输出。

## 通用修复

- Planner 对一图请求单独提取当前主题，明确新主题覆盖旧课程和知识点；省略对象才回指对话。解析异常使用当前请求保守回退，空主题进入澄清，不用固定学科白名单。
- 实际模式下不再用课程名字字面命中裁剪一图资料或判断底稿跑题。所有来源仍经过账户、书本和用户选择范围验证；底稿另做语义核对。演示模式保留本地确定性资料筛选，不冒充模型语义验收。
- 明确不切题的正文最多修正一次；仍不切题不调用生图。来源核对失败改用摘录后，再检查摘录是否回答当前主题，防止无关资料以“安全回退”名义进入图片。
- 核对服务失效是未核对，不当作跑题。保留可用底稿并提示；严格资料模式空资料仍停止生成。来源可用、语义切题与事实正确性不是同一结论。
- 当前请求不属于旧课程时，不自动加入旧课程专属考试记录；一图各提示不再附带旧课程教材、考试数据或掌握度。学习偏好仍保留。
- 工具按钮原先固定写“严格忠于所选资料”，会覆盖用户的允许补充设置；改为遵循用户当前设置，另测无资料按钮入口。解析故障时保留按钮附带的真实问题，不能截断成工具说明。
- 记录 topic_verification、image_attempted、failure_stage；是否调用图片服务以实际尝试记录为准。卡片和摘要区分底稿阶段、资料边界及生图失败，不再把失败统一说成已改资料导读。

## 可重复验收

后端回归：`backend/tests/test_one_page_general_topics.py` 覆盖四学科简称、旧主题覆盖、代词回指、缺少主题、解析故障、一次修正成功/失败、核对不可用、来源回退跑题、图片服务失败、空正文、上传章节没有课程原名、严格空资料及旧考试数据污染。并运行完整后端测试。

浏览器本地：`one-page-feedback.spec.ts` 与 `one-page-review-ui.spec.ts` 检查资料边界、桌面和手机成图状态、失败提示；它们不证明真实供应商可用。

浏览器生产：`one-page-general-live.spec.ts` 在独立测试账户中测试：

| 用例 | 入口/条件 | 验收依据 |
|---|---|---|
| 高数原句 | 已配置六级课程和教材，聊天直接请求 | 高数主题、极限/微分/积分、真实小云雀图片可见，无六级内容混入 |
| 大学物理 | 高数标题书本，无上传资料，允许补充，先问后点工具 | 力学/热学/电磁学、实际图片可解码 |
| 英语语法 | 原创上传分节笔记，严格模式，先问后点工具 | 词类/主干/时态、出处属于所选文件、实际图片可见 |
| 计算机科学 | 旧高数书本，聊天直接请求 | 算法/系统/网络、实际图片可见 |
| 严格空资料 | 资源生成 API | 不可用原因明确，未调用图片服务 |
| 严格无关资料 | 语法笔记→有机化学 | 不生成无关知识图 |

真实验收使用 `scripts/acceptance.py` 的 ReleaseLease，绑定部署版本，前后核对健康接口版本，保存资源、原图、截图、耗时和断言结果到忽略的 `.tmp/general-live/`。失败不能通过反复重试隐藏，修复后重跑保留前次证据。

## 限制及维护

有限样本无法证明所有课程都永远成功。真实图片交付、文字底稿主题正确、课程事实核验、成图文字/公式/关系检查需分别记录。小云雀返回图片不等于其中中文和公式准确；成图检查无法完成时保留“仍需核对”，不能显示已通过。

提示词仍在 `backend/app/prompts/` 按职责独立 Markdown 维护，manifest 登记并随代码版本部署，`prompt_templates.py` 运行时组装。这里是提示词与工作流工程，没有训练或修改模型权重，不是微调。本次主题解析/核对/修正模板均有版本与自动回归，可独立迭代。
