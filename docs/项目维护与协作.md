# 项目维护与协作

## 先记住这四件事

- **MD 是给模型看的说明书。** 一图看懂、英语场景等已有生成规则放在 `backend/app/prompts/`，由程序读取、填入这次问题和资料，再发给模型。模型不会自己去电脑上找文件。
- **代码负责把事情办完。** 包括选功能、调用小云雀、保存图片、检查结果、排队、恢复和展示。换一份 MD 不能修好网络、任务丢失或显示错误。
- **Skill 是开发时参考的工作方法。** 在 Codex 安装 Skill，不代表线上网站自动获得全部能力。要把适用要求接入 Prompt 和程序，并验收真实结果。
- **这些属于 Prompt 与程序维护，不是微调。** 没有训练或修改模型权重。网站发布使用仓库版本；改本机 MD 后仍需提交部署才能在线上生效。

## 出问题先查哪里

| 现象 | 先检查 | 常见修改位置 |
|---|---|---|
| 能生成，但内容、层次或教学风格不对 | 本次输入、所选资料、实际生效的 Prompt | 对应 MD、知识来源、内容校验 |
| 图片没生成、超时、图片打不开 | 任务进度、小云雀提交/查询/下载、展示 | 接口与业务代码、配置 |
| 刷新后找不到结果 | 任务是否入库、后台进程、结果保存 | `services/generation_jobs.py` |
| 多人同时用变慢 | 排队数量、执行时间、服务器内存、供应商限额 | 队列限制、部署容量 |
| 改了规则却没生效 | 生效版本、模板登记、调用位置 | `manifest.json`、`prompt_templates.py`、调用代码 |

一图看懂的主要文件：`doc/one-page.md`（内容底稿）、`image/one-page-visual.md`（画图要求）、`image/one-page-check.md`（图片检查）。以 `manifest.json` 的实际登记为准。英语生成规则在 `english/`；固定版本英语课程在 `backend/app/data/course_library/`，两者分别维护。

## 你给我的信息

最有用的是：**你做了什么、实际出现什么、希望变成什么、哪些内容不能变。** 有截图、原始提问、使用课程、发生时间就一起给；不需要先猜是 Prompt 还是代码坏了。不提供密码或 API Key。

## 可直接复制的维护 Prompt

> 请维护 LearnLoop 的【功能名】。
>
> 我遇到的问题：【操作步骤、原始提问、实际结果，可附截图】。
> 我希望的结果：【用一句话描述用户最终看到什么】。
> 不能改变的内容：【例如继续用小云雀、保留资料与其他功能；没有则写“按现有项目约定”】。
>
> 请先查看当前代码、相关 MD、日志和已有测试，用通俗语言说明原因，判断应该改 Prompt、程序、配置还是课程资料，再执行修复。
> 不要只针对这一个例子写补丁。请选择相关的其他课程、正常与异常输入、刷新中断、重复提交、不同账户做回归；按影响范围选择测试，不无限扩展。
> 如果改生成规则，请维护对应 MD，说明实际调用位置和版本。保留其他任务的改动，不把测试或模拟结果当成真实生成结果。
> 按项目约定完成测试、提交、部署和线上核心功能验收。涉及图片、音频、视频时，既检查能否显示或播放，也检查内容质量；没有检查的部分明确写出。
> 最后简短告诉我：改了什么、怎么验收、还有什么没验证、以后从哪个文件继续维护。普通可恢复的步骤直接做，遇到会删除数据、扩大费用或改变产品方向的决定，再说明影响并找我确认。

如果你只想先了解方案，在末尾加：**“本次只诊断和给方案，先不要改代码或部署。”**

## 怎样合作更省心

1. 每次先给一个明确目标；多个相关问题可以一起列，但标出最重要的一项。
2. 用“某课程 + 原始问题 + 应有结果”作为验收例子。维护时再扩展相邻场景，避免只修截图。
3. 修改后保留失败例子，下次迭代重复验证。好的 Prompt 也可能生成错误，测试应当检查输出内容。
4. 我负责找位置、修改、测试和发布，你负责确认实际学习体验与产品取舍。不要靠你猜技术原因。

## 本次稳定性维护的边界

对话和学习资源生成增加持久任务、恢复和排队；图片仍调用小云雀，MD 继续负责内容要求。刷新/停止等待不会撤销后台任务；回来后从“任务进度/最近任务”查看结果。清空对话会使该对话的未完成任务失效。

已拿到小云雀任务编号时继续查同一任务；提交结果不确定时暂停，避免盲目重复扣费。恢复不等于保证每次都成功。默认生产同时执行 2 个任务、每人 1 个，其余排队；这是当前小服务器的保护措施，不代表已通过大规模压力测试。

图片文字、公式、关系仍需单独验收；“任务完成”只表示生成流程结束。队列不会让错误的知识自动变正确。
